# 0.9.1–0.9.3 能力深化记录

日期：2026-10-30。代码阶段在 `codex/pre-0-9-abilities` 实现并分别提交；此文只记录本次代码与自动化验证，不把本机测试作为跨设备或真实 Harness 验收。

## 0.9.1 共享上下文

`read_context` 提供共同服务、HTTP、MCP 和本地 Git adapter 的只读上下文入口；快照包含 `shared_context`。来源、作用域、观测时间、新鲜度和共享结构化隐私边界明确，不创建消息已读回执。后续完整性检查继续覆盖约定版本、依赖、资产及范围查询。

## 0.9.2 成员与 Harness 能力发现

旧 session 表及返回形状保留；五种新增 Harness 会话保存在加法迁移表，并与旧会话合并查询。多 agent、版本、平台、仓库、分支、任务和登记时间可见。能力矩阵包含七种目标 Harness；配置适配能力、agent 自报和项目成员确认的具体版本/平台证据分别保存。未知组合不外推，凭据撤销显示不可用，登记和验证证据按各自期限标为陈旧。成员验证通过 `record_capability` 项目管理操作记录，agent MCP 不暴露此操作。

## 0.9.3 交付关联

`read_deliveries` / `GET /api/deliveries` 将现有 branch、commit、PR、Release 关系与本地 Git 观测组织为多对多对象，并支持任务反查。未同步的明确关联也可见，建立者、来源、状态同步和陈旧/不可用状态分别展示。Agent 使用 `suggest_delivery` 提出候选；项目管理成员通过 `decide_delivery` 确认或拒绝。确认与现有 GitHub 关联写入同一事务；ownership epoch 改变后的建议不能确认。所有操作均不自动关闭或验收任务。

托管工作台与本机只读看板复用交付展示组件；托管工作台提供建议确认。项目活动添加结构化交付关联事件，保留来源和新鲜度。

阶段验证：交付追溯、GitHub Sync、本地 Git adapter、Git HTTP 与项目活动共 40 项 Python 回归通过；交付组件、既有 Git UI、任务看板、网页会话与本机看板会话回归通过。新增 HTTP/MCP 用例验证 agent 提议、查询与网页管理者决策边界。

## 验证环境

最初基线在全局 Python 3.13 的 user-site 可编辑安装下运行：620 通过、7 失败、1 跳过。失败涉及隔离子进程无法访问 user-site，以及继承 Codex 运行环境导致 Claude 安装测试的预期错误顺序不同。完整收口将使用专用虚拟环境复验。所有测试证据保留在忽略的 `.local/`；不提交凭据或原始会话内容。
