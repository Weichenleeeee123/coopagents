# C2：海外团队订阅与支付设计

日期：2026-10-11。状态：用户已确认并批准实施。目标为海外团队；C3 真实部署与运营验收明确暂缓。本设计延续完整 MIT 开源与免费私有部署，首个支付适配器采用 Stripe。阶段任务见 [C2 实施计划](commercial-c2-plan.md)。

## 方案选择

| 方案 | 本阶段交付 | 取舍 |
| --- | --- | --- |
| Stripe 订阅适配器（建议） | 团队订阅、托管 Checkout、Customer Portal、服务端事件同步 | 单一提供方先做完整；上线时再配置真实商户、价格和密钥 |
| Paddle 订阅适配器 | 同类团队订阅与提供方托管支付流程 | 需要围绕另一套提供方 API 和事件实施，首版不同时维护两个适配器 |
| 只做提供方无关基础 | 套餐、团队账单归属、额度及事件接口 | 不具备提供方支付闭环，真实适配器另行实施 |

建议实现第一种，同时把提供方调用与业务领域分离。市场选择不代表已经拥有可用的支付账户；提供方测试配置与实际验收分别记录，不用模拟结果冒充真实付款。

## 产品范围

计费归属于团队，按团队固定月费订阅，不按模型 token、agent 数或每次消息收费。一个账号可以管理多个团队，每个团队有独立订阅；一个团队最多有一个有效付费订阅。

首版只实现 Free 与 Team 两档。两档均提供完整任务、消息、约定和 agent 协作能力；官方托管通过成员数和项目数区分承载额度。金额、币种、成员与项目上限由部署者明确配置，不能把未确认的数字或测试夹具当作正式售价。Team 对应提供方的一个月付 Price；启用前服务端读取并校验 Price，再展示实际金额、币种和周期。首版不实现年付、按席位调价、折扣、试用开通、企业 SSO 或 SLA。

所有这些源码继续开源。`self-hosted` 模式不执行套餐额度、不要求 Stripe、不挂载支付事件入口，也不访问官方许可服务。`cloud` 模式只有在计费配置完整时启用商业订阅；未配置时保留 C1 行为并明确显示“订阅尚未启用”，不显示假结账入口或已付款状态。部分或相互冲突的配置启动失败。

## 账号与页面权限

在现有团队设置增加“套餐与账单”，不改变项目看板与 agent 使用方式。

- 活跃团队成员可查看当前套餐、成员/项目用量和服务状态。
- 只有当前团队 owner 能发起 Checkout、进入 Customer Portal、发起订阅同步或查看账单管理信息；admin/member 不能用这些接口更改收费状态。
- 账号 Cookie、精确 Origin 和会话 CSRF 继续用于写操作。项目网页或 agent bearer 不能访问账单接口。每次操作及实际发送提供方请求前重查 owner 身份。
- Checkout 成功回跳只显示“正在确认订阅”，等待服务端实际同步；URL 参数、浏览器存储和前端按钮不能升级套餐。
- 提供方未配置、请求失败、付款待处理、支付失败、取消待生效和额度不足均有明确状态。账单页面首次增加清楚的英文文案；全站国际化另列后续工作。

不自行采集银行卡信息。Checkout 与 Portal 由提供方承载，返回地址由服务端固定为规范 origin 下的账单页面，禁止客户端传入任意回跳地址。

## 数据与支付边界

附加迁移保留现有 SQLite 表和数据。新增团队计费绑定、套餐目录快照、订阅状态、待完成结账、事件处理记录与同步审计。账号角色与订阅权益分别保存；支付事件不能修改团队成员角色。

Customer/Subscription 与 team 的绑定由服务端在 owner 授权操作中建立，以内部团队 ID 和已保存提供方 ID 为依据，不通过邮箱、名字或请求中自填的 customer ID 认领订阅。测试与正式模式严格区分；Price、Customer、Subscription 和事件必须属于配置的模式。

支付 SDK/HTTP 与领域状态分离。密钥仅从互斥的环境或受保护文件读取，不进入 Git、常规 API、URL 或日志。提供方请求设置超时、返回体上限及幂等键，在事件循环之外执行；网络调用不持有 SQLite 写锁。订阅入口串行协调同一团队，并在数据库记录未完成结账及唯一绑定，防止重试产生多份订阅。

没有真实提供方配置时，生产接口不能注入“测试付款”或手工把 Free 改成 Team。模拟适配器仅限测试代码；运行服务中没有未认证调试入口。

## 事件、恢复与权益

Webhook 独立于账号 Cookie/CSRF，仅接受提供方对原始 body 的有效签名，并校验签名时间、请求大小和测试/正式模式。公开路由豁免只针对这个精确路径；其他 Host、origin 和 API 边界保持原规则。未启用计费或签名不合法时拒绝，不读取不可信 team 元数据授予权益。

事件 ID 唯一，经过验证的最小必要事件信息和待同步任务先持久化再确认接收。失败任务保留可重试状态，重启后继续处理。事件可以重复、乱序或并发到达；每次针对已绑定订阅从提供方取得最新状态，不按到达顺序覆盖数据库。同步版本/租约保护较早的网络结果不能覆盖后完成的同步。提供方暂不可用时保留已验证状态与最后同步时间，不生成成功记录。

订阅、支付失败、取消、退款和争议事件都触发相应同步或风险记录。当前有效账期的完整退款/未解决争议进入付费权益暂停状态；部分退款保留状态并记录，过去账期退款不直接取消当前账期权益。重复或过期风险事件不能覆盖新的、已核实权益。暂停恢复必须经过提供方当前数据核验，不能仅凭浏览器回跳或单个旧 paid 事件。

已核实的 active 订阅在已付账期内授予 Team。期末取消保留到已付账期结束；立即取消、过期、未付款、暂停或有效风险冻结回落到 Free。首版不自动承诺额外欠款宽限。明确保存权益截止时间，不能因为遗漏事件永久保留付费额度。Portal 修改或取消后，可由 owner 触发服务端同步；同时提供运维命令重试待处理事件与同步绑定订阅，保留审计和原始文件。

## 额度与数据保留

启用 cloud 计费时，限制只针对新增承载，不删除已有数据、不撤销账号身份、不改变已授权项目的协作能力。

- 成员用量统计团队中 active 的账号，包括 owner/admin；尚未兑换的邀请不算成员。兑换邀请或重新加入时在同一写事务中检查容量，失败不消耗邀请，不创建残留账号。
- 项目用量统计已绑定团队的所有项目；创建项目和认领旧项目都必须检查，不能通过迁移入口绕过。
- 降级后超额的团队仍可读写已有授权项目、处理协作、移除成员和管理订阅；禁止进一步新增成员或项目，直到容量符合新套餐或重新升级。
- 不按成员注册的 agent 会话数重复收费。旧项目认领不自动把历史协作者绑定为账号；该兼容边界在页面和文档说明，后续实际托管迁移的完整核验归 C3。

用量与检查使用现有数据库的实际行，和新增写操作在同一事务完成，覆盖并发邀请兑换/建项目。私有部署返回无限制权益，不用伪造付费订阅表示无限制。

## 本阶段验收

1. 两团队账单隔离、角色降级、伪造提供方 ID、agent 越权、Origin/CSRF 拒绝。
2. Checkout 幂等、并发重试、过期结账恢复；回跳不改变权益。
3. Webhook 签名与重放时间、重复/乱序/并发事件、持久化后重启、失败重试及陈旧同步保护。
4. 支付失败、期末取消、立即取消、全额/部分/历史账期退款与争议状态。
5. 真实用量、并发额度、超额降级保留数据，以及自托管完全不受收费限制。
6. 页面空状态、不可用状态、异步切换清理；回归现有 HTTP/MCP、C1、JS、打包与备份恢复。
7. 可配置时单独执行 Stripe 测试模式验收；缺少测试密钥则明确记录未执行。真实收费、正式 Webhook 公网送达和上线运维属于暂缓的 C3。

阶段提交为订阅领域与额度、提供方/API/事件、网页、文档和验收。维护文档仍位于 `docs/`；本机配置、密钥、原始支付测试数据保留忽略目录。永远不删除文件。
