# 邀请链接与 Skill 接入验收

验收日期：2026-10-12。

## 已实现

项目卡片「邀请队友」默认邀请普通成员并仅授予当前项目；团队设置保留多项目/角色选择。邀请是 24 小时单次链接，fragment 在首个脚本内清除，预览不消费；新账号注册或已有账号明确接受后进入指定项目。已有团队成员通过链接获得新增项目访问，不改变角色、不重复占成员额度。链接页面刷新/关闭后需重开原链接；GitHub 登录在新标签页进行，原邀请页保留上下文。

项目「接入 agent」选择原生工具后，点击生成并复制包含 Skill URL、协议、服务、项目、工具、个人 agent 凭据的私有指令。此设计按用户明确要求包含凭据，不增加第二次设备授权或本地 Crewmesh 工具。服务仅允许本人项目 web 身份发行额外 90 天 agent 凭据，保留已有连接；退出网页或关闭弹窗不会撤销已配置的 agent，项目权限撤销或令牌轮换会使其失效。

公开 SKILL.md 和 protocol.md 经资源路由提供，纳入 wheel；Skill 安装只保存公开说明，成员凭据保留在原生私有 MCP 配置中。指令不写持久浏览器存储，弹窗关闭、退出、切换项目或工具清空，并阻止迟到响应重新展示。

- 8 组 Node 网页行为回归通过（含邀请、接入、会话、Billing 29 组、Git、检查点、任务生命周期和依赖）；所有网页 JS 语法检查通过。
- Skill frontmatter 验证通过；sdist 与 wheel 构建通过，独立检查 Skill、协议、邀请网页资源存在，无本机数据库混入。
- 真实浏览器：已有团队成员登录并明确接受后进入 Project Alpha；新成员通过链接注册进入项目，生成私有 Skill 指令，以其中的凭据验证服务返回当前项目 agent 身份，关闭弹窗后清空指令。390 × 844 接入弹窗截图已检查，无横向溢出。
- 邀请独立审查发现的旧接受请求导航、新邀请被旧结果污染、失败预览恢复三项问题已补充延迟响应回归并修复。最终审查再发现注册响应覆盖新邀请、无效链接残留旧隐藏值两项问题，均先复现失败，再补齐注册责任版本检查和输入清空；新增六种组合回归通过。

## 边界

本阶段没有修改本机真实 Claude / Codex 配置，没有宣称这段 Skill 已在真实模型中完成安装或原生 MCP 热加载。不能从直接 HTTP 成功推断当前原生会话已接入；需原生会话实际调用 whoami/read_team/checkpoint 验证。原生自动上下文消费、空闲唤醒和真实 GitHub OAuth 往返仍须独立验收。Skill 不要求旧 Python hook 或本地 Git adapter。

原始证据在忽略的 .local/onboarding-qa/；测试数据和凭据不纳入 Git。没有删除任何文件。
