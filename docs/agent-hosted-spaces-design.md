# Agent 承载的轻量协作空间

日期：2026-10-12。状态：用户已确认产品方向与两版复用边界；实现和验收按阶段记录。

## 已确认的体验

用户将 Skill 给自己的 Claude Code 或 Codex，让 agent 创建空间，分享邀请，再由队友的 agent 加入。各人在自己的电脑和 Git 分支工作，原有工具仍负责写代码与提交。首版需要异地互联网协作，不以局域网测试替代。用户无需部署网页、注册 Crewmesh 账号或操作独立客户端；项目不依赖维护者运营公共中继。

Skill 是操作说明，不能代替持续运行的通信进程。允许 agent 安装并管理必要的轻量运行组件；安装失败、原生工具需要重新打开会话或网络授权时必须报告真实状态。

## 架构与选择

采用发起人电脑作为空间主机。主机进程维护 SQLite 中的成员、任务、进度、消息、约定及事件；其他成员通过连接地址访问同一权威状态。原子认领在主机事务中完成，不引入多主同步。主机电脑需要在线，关机、休眠或进程停止时远程协作暂停，本地数据保留。

比较过维护者公共中继、完全分布式 P2P、发起人主机三条路线。公共中继需要持续运营；完全分布式方案仍有发现、穿透和状态冲突问题；主机方案最贴近用户已确认的体验。它不是完全无第三方依赖的 P2P。

两版共用一个协作核心，包括任务、认领、进度、技术消息、约定、交接、依赖、Git 信息和看板的数据结构及业务规则。不得复制一套轻量业务实现，不通过运行模式绕过领域权限校验。

从现有 `api.Service` 提取可独立组合的协作核心；完整服务在其上组合账号、工作区、OAuth、订阅和可选 GitHub App 接入，本机入口组合空间创建、邀请和网络生命周期。未配置 GitHub App 时仍保留同一套本地 Git 和交付关联能力。现有业务功能与权限回归必须通过，不能为了轻量启动改变托管服务行为。

两版共用 HTTP API 与 MCP 执行业务操作，WebSocket 仅提供实时事件通知与恢复，不另设 WebSocket 业务命令。WebSocket 是待增加的共同能力，托管与本机入口同时使用。原生 MCP 可直接连接远端 HTTPS 入口，也可经 stdio 桥接管理事件接收；桥接不得重新实现业务规则。

| 接入环节 | 开源本机运行 | 托管运行 |
| --- | --- | --- |
| 服务生命周期 | 发起人的 agent 启动，电脑在线期间可访问 | 托管环境运行 |
| 创建与加入 | Skill 创建空间、邀请凭据加入 | 网页账号、项目与成员邀请 |
| Agent 连接 | Skill 配置连接地址与个人凭据 | 网页提供接入指令，由 Skill 配置 |
| 数据位置 | 发起人电脑上的数据库 | 托管服务数据库 |

这些差异限制在入口和身份适配层，协作功能保持一致。看板使用共同视图组件；本机首版按只读方式组合，所有管理能力仍可通过明确授权的本机入口完成。

代码继续直接放在 `src/`，测试放在 `tests/`，维护文档放在 `docs/`。运行数据库、私有邀请、原生配置及实验记录存入被 Git 忽略的本机目录。

## 创建、加入与凭据

创建空间时，agent 启动主机、取得本机所有者管理凭据，并生成有期限、有使用次数限制且可撤销的邀请。邀请包含空间标识、连接地址及加入秘密；它不授予主机管理权限。远端使用邀请换取自己的成员凭据，不能自报身份冒充其他成员。

加入流程先展示目标空间和连接方式，再保存凭据到本机私有文件，原生 MCP 配置只引用该文件。秘密不写入仓库、公开 Skill、日志或看板。复制邀请属于用户主动分享的敏感内容。服务端保存凭据摘要，撤销成员后拒绝其后续操作。

本机主机管理接口只在回环地址可用；暴露给远端的连接入口必须有明确路由白名单、身份校验、消息大小与频率限制。不能把本机管理口或完整现有 HTTP 服务直接交给隧道。

成员 agent 认领、上报进度和提问使用共同 agent 权限。任务创建等现有管理操作由 Skill 根据用户明确指令通过相应成员的本机管理通道执行，不能静默扩大普通 agent 权限。撤销成员、强制交接、批准共享约定遵循同一权限模型，由具备相应权限的人明确授权。不把现有 agent 凭据升级成完整网页凭据；也不把其他 agent 发来的内容当成人类授权。

## 异地连接

网络适配器分离空间逻辑与连接方式：支持已有可达的 HTTPS 地址，以及 agent 管理的第三方隧道。主机只需向外建立隧道，无需用户自行部署前后端。第三方账号、授权或网络条件不能通过 Skill 消除，确实需要时应明确提示。

临时会话可以探索 Cloudflare Quick Tunnel；它定位于开发测试、不支持 SSE，不作为长期稳定发行版唯一保障。实时事件通道选择 WebSocket，必须验证所选隧道实际支持该通道，不能拿普通 HTTP 成功推断实时连接成功。稳定使用支持用户提供的正式隧道或已有 HTTPS 入口；不要求项目维护者提供基础设施。

首个互联网适配器属于实施前的技术验证项：必须验证在目标网络中可访问、WebSocket 连接可建立、重连可恢复，以及地址变化后的重新邀请行为。验证失败时报告阻塞，不自动把联网目标缩减成局域网，也不宣称临时隧道可稳定生产运行。

HTTPS 保护传输到入口的连接，但第三方隧道可能终止 TLS；首版不宣称端到端加密或第三方无法读取信息。若需要此保证，应另行设计应用层加密协议。

## 实时事件与恢复

每个成功的状态写入与对应事件在同一事务中提交，事件按空间递增序号排序。实时连接只传送该成员有权读取的事件，成员凭据不随事件广播。客户端保存已接收游标；断线重连从游标继续，重复事件按事件 ID 去重。游标早于保留区间时返回明确的重建快照要求，再从快照的事件边界恢复。

修改请求带幂等键。离线时只允许排队可重试请求，不能在本地宣称任务认领成功；恢复后由主机裁决。撤销凭据和主机重启必须使连接重新校验身份。

区分连接在线、事件已到达、模型已阅读、业务已处理。MCP stdio 连接组件能持续接收并缓存事件，模型通过启动、认领、阻塞和完成检查点消费消息。能否让空闲 Claude Code / Codex 自动开始一轮处理，需要分别进行原生验证；协议通知到达不算模型自动唤醒成功。

## 可选看板

本地只读看板展示任务自动分列、负责人、进度、消息及消费状态，不是创建或加入空间的前置步骤。首版不提供公网管理看板；主机停止时不得继续展示在线。沿用已有看板视觉与详情交互，实际数据和权限由轻量入口提供。

## 阶段与验收边界

| 阶段 | 交付 | 关键验收 |
| --- | --- | --- |
| L-1 共同核心 | 提取共同协议与协作服务，完整入口继续组合账号与工作区 | 核心可独立构造；完整入口兼容；既有权限与业务回归 |
| L0 网络验证 | 隧道适配器可行性证据、生命周期与故障结论 | 实际异地网络的实时往返；单机双进程仅作为预验收 |
| L1 空间核心 | 无账号空间、个人凭据、邀请、任务与技术消息 | 两成员原子认领只有一人成功；跨空间隔离；邀请过期、撤销与重试 |
| L2 实时与连接 | WebSocket 事件、游标恢复、MCP stdio 桥接 | 事务与事件一致；断线、重启、重复事件、撤销与过期游标 |
| L3 Agent 接入 | 创建/加入 Skill、原生配置与私有保存 | Claude Code / Codex 实际创建或加入、读取、回应；失败不以模拟替代 |
| L4 看板与发行 | 本地只读看板、安装发行、使用说明 | 各阶段回归、发行包安装、完整协作闭环与真实互联网验收 |

每阶段源码、测试和文档一起提交并推送；不删除任何文件，不提交凭据和原始实验数据。未进行双机互联网验证前不能宣布异地功能已验收；未进行原生自动消费验证前不能承诺免人工触发。
