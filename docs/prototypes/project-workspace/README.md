# 项目工作台信息架构原型

本地可点击原型，用来验证已确认的六项项目入口、项目/团队/个人层级及跨对象查找路径。当前数据全部为合成展示内容，页面修改只存在于浏览器内存。

## 打开方式

在仓库根目录启动静态服务：

```powershell
python .local/ia-prototype-server.py
```

然后打开 `http://127.0.0.1:4173/`。需要第一次设置一个本地端口并运行该脚本；不需要登录，也不请求正式后端。停止服务可在运行终端按 `Ctrl+C`。

纯数据路由和查询回归：

```powershell
node tests/workspace_prototype_regression.js
node --check docs/prototypes/project-workspace/app.js
node --check docs/prototypes/project-workspace/data.js
```

## 建议按这些问题检查

1. 概览是否主要用于判断项目现状，而不是替代所有功能页？
2. 点击「需要关注」里的 R-11，能否确认谁提问、谁回应、问题是什么？返回后位置是否容易辨认？
3. 从任务 CP-024 打开详情，能否找到请求 R-12 和 PR #42，再从 PR 回到相关任务？
4. 切到成员与 agent，是否能把一个人的多个工具会话分开查看，并区分登记、连接、事件送达、模型处理和能力证据？
5. 在共享上下文里，约定、文件、共享记录各自的内容和用途是否清楚？
6. 在成员页点击 agent 详情时，是否有工具/版本/状态/独立能力证据，而不会出现 Harness 支持矩阵？
7. 交付页的分支轨道是否讲清父级来源，点 PR/分支后是否能回任务？图是否明确说明合成数据？
8. 在 390px 手机宽度下，项目菜单、当前页面与详情返回是否可发现？
9. 进入只读预览后，管理动作是否收起，关联对象是否仍能查看？
10. 在全部项目中切到「新项目」，空状态和返回其他项目是否明确？

## 与正式页面的边界

原型静态显示六个项目页以及项目设置、团队管理、个人账号和全部项目入口。它不连接服务、不处理真实凭据、不验证 Harness/网络状态、不对外通知，不执行创建请求或 GitHub 操作；`演示编辑` 的操作只在当前页面暂存。不需要安装或提交第三方 JavaScript 库；图标是 Lucide/Feather SVG 路径，授权见 `icons.js`。
