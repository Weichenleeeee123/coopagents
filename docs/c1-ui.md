# C1 account workbench

The single workbench opens with account login. `/account/config` determines whether local login, first-account bootstrap and invitation registration are available, or whether the real GitHub OAuth navigation is enabled. A cloud deployment without OAuth configuration displays its unavailable state. The expandable legacy entry retains unbound local project creation, invitation redemption and explicit bearer restoration; cloud permits only restoration.

An authenticated account sees its teams, accessible projects and team members. Team managers can create projects, issue invitations with explicit unchecked project scopes, and claim an unbound project with its owner web credential. Member management separates team roles from project access. Metadata from `managed-projects` never makes a project selectable. The UI protects the last owner and limits administrators to ordinary member targets; every operation is also authorized by the server. Local password changes revoke sessions; administrative resets show the exclusive-team restriction and surface server errors.

`accounts.js` owns account state inside an IIFE. Account cookies remain HttpOnly; CSRF stays in memory. Account fetches use same-origin credentials, with CSRF on authenticated writes and the browser's Origin header. Loading is sequential, respecting the server's two-worker bound. Forms clear transient password and invitation fields. One-use invitation secrets use the existing private dialog, which clears its content on close.

`window.CrewmeshProject` provides `enter`, `clear`, `private` and `managed` to the account controller. Only the selected project's scoped bearer and selected team/project IDs use tab storage. A marker gates stored account-project restoration until `/account/session` succeeds and the project is reselected on the server. `window.CrewmeshAccounts.home` returns to the hub; `denied` rechecks the cookie when a project bearer is rejected. Account permission 401 responses recheck `/account/session` and preserve a valid account.

Every switch or logout invalidates generations, aborts pending requests, clears private rendered data and closes credential/task dialogs. Checks after JSON parsing prevent delayed response bodies from repainting a replaced session. Account logout revokes the server session before completing the local sign-out; a failure offers retry. The project exit button returns to the account hub.

Validation: `node tests/account_ui_regression.js src/static/accounts.js` covers delayed account/project/team responses, project bridge selection, cookie/CSRF writes, empty invitation scopes, account-secret storage and valid-cookie permission denials. Existing `web_session_regression.js` passes. `python -m unittest discover -s tests -p test_web.py -v` passes all five tests, including real packaged asset serving and both Node regressions. Browser acceptance is performed separately with isolated local data.

Browser selectors: `#account-login`, `#bootstrap-form`, `#register-form`, `#hub-team`, `#team-form`, `#project-form`, `#hub-projects`, `#team-invite-form`, `#invite-scopes`, `#accept-form`, `#hub-members`, `#claim-form`, `#password-form`, `#account-logout`, `#workspace-team`, `#workspace-project`, `#account-settings`. Existing task board/detail and agent connection selectors remain unchanged.
