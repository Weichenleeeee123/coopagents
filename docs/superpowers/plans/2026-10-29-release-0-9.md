# 0.9 Shared Assets and Harness Adapters Implementation Plan

> **For agentic workers:** Follow this plan stage by stage. Keep all files, retain test evidence, and commit each verified stage independently.

**Goal:** Deliver explicit project asset sharing, reviewable self-hosted activity and Git delivery views, and safe MCP setup for Cursor, OpenCode, Pi, Kimi Code, and ZCode.

**Architecture:** Extend the shared coordination domain so P2P spaces and self-hosted accounts use the same project-scoped asset contract. Store uploaded bytes under a configured private data root and metadata in SQLite; expose bounded authenticated upload/list/download routes and explicit UI actions. Keep harness-specific configuration adapters thin and capability-reported, with the existing MCP protocol as the shared behavior.

**Tech Stack:** Python 3.11+, SQLite, Starlette, existing static JavaScript UI and regression harnesses, Node.js tests, official harness MCP configuration formats.

---

## Scope and invariants

- Project assets are shared only after an explicit member action. Never recursively scan a repository or upload an entire workspace.
- Store asset ID, project ID, uploader identity, display name, media type, byte count, SHA-256, source reference when explicitly supplied, and timestamps. Enforce configurable per-file, per-project and total storage limits.
- Read and download require current project membership. Revoked members immediately lose access. Downloads use server-generated storage keys, fixed content headers, and no executable inline rendering.
- Keep file bytes outside SQLite so existing SQLite online backup remains consistent; document and test coordinated data-root backup/restore. Database-only backup must report that asset bytes are not included.
- Activity contains only typed collaboration actions, explicit progress reports, Git observations, and verified remote Git facts. Never read or persist full prompts, replies, reasoning, tool I/O, or harness transcripts.
- Preserve the read-only local P2P board boundary. No remote web management routes are added to a host-local P2P space.
- Harness adapters install or print only supported official MCP configuration, preserve unrelated configuration, and report MCP/project-context/native-hook capabilities honestly. No adapter parses private conversation logs.
