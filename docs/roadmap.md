# Crewmesh 后续任务路线

更新：2026-10-10。持续维护本文件；每个代码阶段测试和审查通过后独立提交 Git。任务详情在对应实施计划中，证据进入验证报告。

## 当前依据

Claude 正常入口发布、Codex 桌面读取和显式确认已通过。既有桌面会话在普通任务中自行发现了新消息，有条件通过任务检查点拉取。全新会话、Codex hook 触发、运行中消费和双机协作仍未通过。

据此继续实现共享服务，以任务检查点同步为首版基础。接入研究继续独立推进，网页必须展示待消费和未确认状态，不承诺即时推送。

| 阶段 | 具体任务 | 验收依据 | 状态 |
| --- | --- | --- | --- |
| P2.1 身份基础 | 房间、成员、网页和 agent 分别持有凭据、撤销 agent 凭据 | 跨房间不可见；agent 不能执行网页管理操作；数据库不保存明文凭据 | 领域实现与 13 项测试通过 |
| P2.2 任务认领 | 人建立任务、agent 原子认领、重复请求幂等、已认领任务冲突 | 不同成员同时认领只有一个成功；失败方知道本房间已有负责人 | 领域实现与 12 项任务测试通过 |
| P2.3 状态与重复提示 | 会话关联成员、分支和入口；声明任务状态；相同意图与模块范围重叠提示 | 连接活跃不等于开发中；重叠只作为有依据的提示 | 实现与 10 项活动测试通过 |
| P2.4 技术消息 | 指定接收方、提问、回应、读取证据、处理确认、分页与离线恢复 | 只读消息不能自动标已解决；断线后仍可消费；重试不重复发送 | 实现与 11 项消息测试通过 |
| P2.5 共享约定 | 提案、不可变版本、来源消息与提交标识、人工批准 | agent 补充细节为待确认；旧版本回应不能关闭新版本问题 | 实现与 8 项版本测试通过 |
| P2.6 服务入口 | 同一领域服务提供网页 HTTP API 与 authenticated MCP，凭据绑定调用身份 | 不接受自报 author/receiver 冒充；未授权请求被拒绝；真实 HTTP 测试通过 | 邀请 8 项、真实传输 6 项测试通过；完整 68 项通过 |
| P3 网页 | 加入和连接检查、团队工作卡、任务详情、技术请求、人工决定 | 全部状态来自服务数据；断线、待消费、待确认有清楚展示 | 已完成本机验收；完整 72 项通过；网页提交 bac08a0 |
| P4 双机试用 | 两位成员在各自电脑和原有工具中协作，同一仓库不同分支 | 识别一次重复工作、完成一次技术问答、恢复一条离线消息 | 待实施 |
