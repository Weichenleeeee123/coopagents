## P2.6 HTTP / MCP

提交 `ccfb6fe`，源码末尾格式修正 `9d07db2`。3 项真实回环 HTTP 测试与 3 项官方 SDK MCP 测试通过，主代理独立运行完整 68 项测试通过，两阶段审查通过。两个个人凭据客户端并发调用，完成认领竞争、读取/处理/回复/解决请求、提案与 HTTP 人工批准；另一房间读取为空，跨房间任务和来源被拒绝且不泄露负责人。

MCP 使用官方鉴权上下文和 stateless Streamable HTTP，不宣称提供 OAuth 服务；每个工具再次校验原凭据。原始工具参数在类型转换前检查，拒绝自报 author 和 bool ID。HTTP/MCP 限制实际正文大小、Host 与写入 Origin，错误不输出异常内容，响应禁止缓存，关闭访问日志。默认服务为本机 `8787`，数据库与旧实验独立。测试结果不代替原生双机或闲置唤醒验收。

浏览器通过本机 `8789` 的独立 SQLite 验收库访问真实 API，虚构 QA 成员和任务只用于验收，不注入产品页面。实际操作覆盖：

- 创建团队、恢复访问、签发邀请并在独立标签页兑换；普通成员不显示创建者邀请入口。
- 创建任务，重复标识不同内容返回冲突并保留草稿；键盘导航、刷新保留输入。
- 指派未分派请求，读取/处理不自动产生；由原发起人成员确认已有回复的请求解决。
- 批准 v1、提交待审 v2、拒绝 v2，当前版本为 2 而生效仍为 1，版本和审核事件保持历史。
- 断网保留最后团队数据、提示同步时间，恢复连接后重新同步；网页凭据过期后退出并隐藏私密弹窗。
- 个人 agent 令牌轮换、密码遮罩与 Escape 隐藏；配置模板使用 TOKEN 占位符。
- 380 像素视口无横向溢出；脚本注入测试标题作为纯文本，未生成 img 节点。

审查期间修复 response.json 等待后以及创建、加入、恢复、任务与凭据回调的会话切换竞态。回归直接执行实际 app.js，并覆盖旧响应不能退出新会话或覆盖新凭据、旧任务回调不能清空新草稿；恢复访问 guard 的缺失版本在保留的本机副本中先失败，补齐后通过。
