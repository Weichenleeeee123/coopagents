# Windows 原生连接的宿主恢复

日期：2026-11-01。范围：修复 Codex 沙箱结束命令后，已创建空间的后台宿主退出，后续 doctor 和原生会话无法连接的问题。

## 已确认的约束

同一 Windows 原生沙箱内，普通后台子进程在命令结束后退出；普通宿主中的对照子进程继续存活。不能靠启动重试或改变凭据修复这一生命周期差异，也不能自动逃离沙箱。原生 MCP 服务是用户通过 connect 明确注册的应用入口，应负责恢复它所连接的本地 owner runtime。

## 方案

使用原生 MCP 连接恢复已授权的 owner runtime。没有选用 Windows 系统服务或计划任务，避免安装额外系统级组件；也不要求关闭沙箱。保留原 CLI 后台启动方式，修复其在原生会话之间的恢复行为。

显式 connect 成功注册 owner 连接后，为 local/p2p 宿主写入私人、绑定 room/member 的生命周期记录。成员、远端 hosted profile、未连接的旧 owner、quick tunnel 均不自动启动。连接重装不解除显式停止或启动失败锁定。

原生 bridge 在验证身份前检查该记录：运行中的宿主直接复用；已授权且意外退出的宿主由原生 MCP 入口恢复，继续使用原 profile、数据库、端口和 P2P key。多个会话使用同一跨进程管理锁，防止重复启动。运行失败后锁定自动重试，要求显式 start 后再尝试，避免无限创建进程。

显式 stop 先记录暂停，再停止服务；后续 bridge 重连不能自动复活它。显式 start 恢复运行意图并解除失败锁定。doctor 保持只读，不在诊断中创建进程；当原生命令宿主已退出时，明确提示打开新原生会话，并区分配置、已完成挑战、当前可达性和原生身份核验。

不新增普通 agent 可调用的宿主启动/停止工具，不改变授权角色、工具权限或目标地址。私人记录和日志继续保留，不删除文件。

宿主在线期与原生 owner 会话相关：真实 Windows Codex exec 的整个会话退出后，MCP 的子进程树也可能被回收。协作时保持至少一个 owner 原生会话打开；关闭所有 owner 会话后，其他设备不能访问已离线的主机，直到下一次会话恢复。此方案不承诺关闭应用后全天候托管；需要全天候服务时应使用既有独立部署路径。诊断的在线挑战在原生会话打开期间独立执行；会话关闭后的只读数据库核对只能证明先前挑战完成，不能证明当前在线。

## 验收

1. 红绿回归覆盖真实 owner 宿主丢失后的 bridge 恢复、显式停止不复活、显式恢复、两个会话竞争启动、记录身份错配及成员/未配置 owner 不启动宿主。
2. 启动失败只能自动尝试一次，后续读取不能反复启动；显式 start 可解除锁定。
3. doctor 保持只读；已完成挑战使用持久证据核对，不由验收器代启动宿主。
4. 真实 Windows Codex 使用正常沙箱执行创建和连接；命令结束后新原生会话恢复宿主，实际 whoami/read_team 与保存身份匹配；独立 doctor、文件问答、停止后新会话不复活及显式恢复均需真实验证。
5. 完整回归及 CI 通过后更新 P0 记录。不能把配置成功或模拟测试替代原生验收。
