# P4 可部署发行版计划

用户确认：先交付完整可部署发行版，部署目标稍后提供。保持现有 Claude Code / Codex 工作方式；网页查看自动任务看板。

## 阶段与验收

1. 公开仓库许可与发现性：MIT License、GitHub Topics。已完成。
2. 公网配置：默认继续仅本机访问；显式 HTTPS 公网 origin、严格 Host / Origin 校验、受控建房入口、显式代理信任、就绪检查；真实 HTTP / MCP 回归测试。
3. 发行与运维：非 root Docker 镜像、Caddy HTTPS 反向代理、持久卷、示例环境配置、CI；SQLite 一致备份和不覆盖原数据的恢复；操作文档与测试。
4. 协作验收：在单机隔离两个成员及工作目录，通过正式服务验证抢占、技术请求、确认、回复、版本决策与重启持久化；尝试真实原生 CLI，保留本机证据。
5. 发布：完整回归、打包安装验证、独立审查、更新 README / roadmap / 验收报告、分阶段 Git 提交、推送 GitHub 并提供发行资产。

## 边界

- 单机多进程验收不能代替物理双机、实际公网 TLS 和网络故障验收。
- 不宣称 agent 在空闲时自动唤醒；协作信息通过工具调用及工作检查点拉取。
- 未提供部署目标，因此不执行真实公网部署；记录后续部署验收步骤。
- 原始日志、凭据、数据库保留于被 Git 忽略的 `.local/`。不删除任何文件。
- 每个阶段记录实际执行的检查及限制，失败或未执行项目不能写为通过。
