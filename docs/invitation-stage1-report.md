# 邀请链接阶段验收

## 已实现

账号项目卡片的“邀请队友”默认邀请普通成员访问当前项目；团队设置保留高级角色与项目范围选择。复制内容为 `/#invite=…` 链接，沿用 24 小时单次邀请。旧版房间邀请仍使用自己的令牌流程。

网页第一个脚本读取邀请 fragment 并立即从地址栏清除，只在当前页面内存和必要的表单输入中保留邀请。预览通过同源 `POST /account/invites/preview` JSON 请求体传递值，不消费、不创建账号、不返回秘密，响应禁止缓存。过期、已用、撤销、发起者失去当前权限均拒绝。

已登录用户明确点击接受；本地登录保留当前页邀请，注册自动填入邀请并显式接受。成功接受单项目邀请后直接进入项目，多项目邀请返回团队项目列表供选择。已有团队成员保留原角色并获得指定项目访问，不重复计入成员容量；管理员邀请不能绕过管理员对其他特权成员的项目授权限制。

## OAuth 与刷新边界

GitHub 登录从邀请页面在新标签页打开，原页面显示“我已完成登录”按钮，返回后重新读取同源 HttpOnly 会话并显示显式接受按钮。邀请值不写浏览器持久存储、不放 OAuth 参数。关闭或刷新原页面需重新打开原邀请链接；页面明确提示此边界。真实 GitHub OAuth 第三方往返仍需部署凭据与人工验收，Node 测试仅验证标签页与会话刷新行为。
